# Интернет-магазин на FastAPI

Веб-приложение интернет-магазина с регистрацией и авторизацией пользователей, каталогом товаров, категориями, корзиной, оформлением заказов и административной панелью.

Проект написан на Python с использованием FastAPI, SQLAlchemy, SQLite и Jinja2.

## Возможности

### Для покупателей
- Регистрация и вход в аккаунт.
- Хранение паролей в виде Argon2-хешей.
- Просмотр каталога товаров.
- Поиск по названию и описанию товара.
- Фильтрация товаров по категориям и подкатегориям.
- Просмотр карточек товаров с изображениями.
- Добавление товаров в корзину и изменение их количества.
- Оформление заказов.
- Просмотр истории заказов и их статусов.
- Повторная попытка оплаты заказа, если предыдущая оплата не прошла.

### Для администратора
- Отдельная административная панель.
- Добавление товаров и загрузка изображений.
- Создание категорий и вложенных подкатегорий.
- Назначение товарам категорий.
- Импорт каталога из JSON-файла.
- Просмотр заказов всех пользователей.
- Изменение статусов заказов.

### Оплата
По умолчанию используется тестовый платёжный провайдер (`fake`). Он позволяет имитировать успешную или неуспешную оплату без подключения внешней платёжной системы.

Архитектура `payments.py` предусматривает подключение другого провайдера: необходимо реализовать создание платежа и проверку входящего webhook.

## Технологии

- **Python**
- **FastAPI** — серверная часть и маршрутизация.
- **SQLAlchemy** — работа с базой данных.
- **SQLite** — хранение пользователей, товаров, категорий, корзин и заказов.
- **Jinja2** — HTML-шаблоны.
- **Argon2** — хеширование паролей.
- **Starlette SessionMiddleware** — сессии пользователей.
- **Uvicorn** — ASGI-сервер.

## Установка и запуск

### 1. Клонирование проекта

```bash
git clone https://github.com/kuaars/apilogin.git
cd apilogin
```

Если проект уже скачан архивом, распакуйте его и перейдите в каталог `apilogin`.

### 2. Создание виртуального окружения

```bash
python -m venv .venv
```

Активация в macOS / Linux:

```bash
source .venv/bin/activate
```

Активация в Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Запуск приложения

```bash
uvicorn main:app --reload
```

После запуска приложение будет доступно по адресу:

```text
http://127.0.0.1:8000
```

Для остановки сервера нажмите `Ctrl+C`.

## Создание администратора

Сначала зарегистрируйте обычного пользователя через страницу:

```text
http://127.0.0.1:8000/register
```

Затем, из корневой папки проекта и при активированном виртуальном окружении, выполните:

```bash
python ad.py <логин>
```

Например:

```bash
python ad.py admin
```

После этого пользователь сможет открыть административную панель:

```text
http://127.0.0.1:8000/admin
```

Скрипт `ad.py` не создаёт нового пользователя — он назначает администратором уже зарегистрированный аккаунт.

## Импорт каталога из JSON

В административной панели предусмотрен импорт каталога из JSON-файла. Пример структуры находится в `example/catalog_example.json`.

Основные поля:

- `categories` — список категорий верхнего уровня.
- `name` — название категории.
- `products` — товары, относящиеся к категории.
- `subcategories` — вложенные категории.
- `description` — описание товара (необязательное поле).
- `price` — цена товара, целое неотрицательное число.

Пример:

```json
{
  "categories": [
    {
      "name": "Электроника",
      "products": [
        {
          "name": "Беспроводные наушники",
          "description": "Bluetooth 5.3, до 30 часов работы",
          "price": 4990
        }
      ],
      "subcategories": [
        {
          "name": "Аудио",
          "products": [
            {
              "name": "Портативная колонка",
              "description": "Защита от воды",
              "price": 2990
            }
          ]
        }
      ]
    }
  ],
  "products": [
    {
      "name": "Подарочная карта",
      "description": "Номинал 1000",
      "price": 1000
    }
  ]
}
```

Товары из корневого массива `products` не привязываются к категории. При повторном импорте совпадающие товары в той же категории обновляются, а не дублируются. Импорт выполняется целиком: если данные содержат ошибку, изменения откатываются.

Ограничения, предусмотренные приложением:
- размер JSON-файла — до 2 МБ;
- максимальная глубина вложенности категорий — 6 уровней.

## Изображения товаров

Изображения загружаются через административную панель и сохраняются в каталоге `uploads/`.

Поддерживаемые форматы:
- JPG / JPEG
- PNG
- GIF
- WEBP

Максимальный размер одного изображения — 5 МБ. Формат проверяется по содержимому файла.

## Платёжный провайдер

По умолчанию приложение использует тестовую оплату. Чтобы выбрать провайдера, используется переменная окружения:

```bash
PAYMENT_PROVIDER=fake
```

Для подключения реальной платёжной системы нужно:

1. Создать класс на основе `PaymentProvider` в `payments.py`.
2. Реализовать метод `create_payment()`, который создаёт платёж и возвращает его идентификатор и ссылку для оплаты.
3. Реализовать `parse_webhook()`, включая проверку подписи уведомления.
4. Добавить выбор нового провайдера в `get_provider()`.
5. Указать имя провайдера в `PAYMENT_PROVIDER`.
6. Настроить в личном кабинете платёжной системы адрес webhook:

```text
https://ваш-домен/payments/webhook
```

Заказ переводится в статус оплаты после обработки уведомления платёжной системы. Текущий `FakePaymentProvider` предназначен только для тестирования.

## База данных

При запуске приложение подключается к SQLite-файлу `users.db`. Если таблицы отсутствуют, SQLAlchemy создаёт их автоматически.

В проекте используются модели:
- `User` — пользователи и признак администратора;
- `product` — товары;
- `Category` — категории и связь с родительской категорией;
- `CartItem` — позиции корзины;
- `Order` — заказы;
- `OrderItem` — состав заказа.

Перед обновлением или переносом проекта рекомендуется сделать резервную копию `users.db` и каталога `uploads/`.

## Важные замечания перед публикацией

Текущая конфигурация рассчитана прежде всего на локальный запуск и разработку. Перед развёртыванием в интернете необходимо:

- заменить встроенный `secret_key` в `main.py` на длинный случайный секрет и вынести его в переменную окружения;
- не публиковать `users.db`, `.venv/`, `.git/`, `__pycache__/` и пользовательские загрузки без необходимости;
- использовать HTTPS;
- настроить резервное копирование базы данных и изображений;
- подключить реального платёжного провайдера, если требуется принимать настоящие платежи;
- проверить настройки доступа и безопасности перед запуском в production.
